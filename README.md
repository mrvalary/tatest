# Проверка КС-грамматики на LR(k)

## Запуск на Windows

[Скачать LrkChecker-Windows-x64.zip](https://github.com/mrvalary/tatest/raw/refs/heads/windows-x64/LrkChecker-Windows-x64.zip)

Распакуйте архив. Откройте `Windows-x64/LrkChecker.exe`. Сборка включает среду .NET и предназначена для Windows 10/11 x64.

1. В окне грамматики выберите готовый пример или укажите алфавиты **Vₜ**, **Vₙ**, начальный символ и правила. За один символ грамматики принимается один знак. Пробелы в полях алфавитов можно использовать как разделители.
2. Укажите целое **k** от 0 до 32 и нажмите **Проверить**. При конфликте откройте соответствующую строку. В объяснении видны состояние, контекст, конкурирующие действия и породившие их ситуации.
3. Откройте страницу пошагового разбора после успешной проверки. Введите цепочку, состоящую из терминалов. Для пустой цепочки оставьте поле пустым или введите `ε`. Выбирайте шаги, чтобы увидеть магазин, остаток входа и причину действия.

Правила записываются по одному на строку. Допустимы стрелки `→` и `->`. Варианты правой части разделяются знаком `|`. Пустую правую часть обозначайте `ε`. Например:

```text
S → Aaa | Bab
A → c
B → c
```

Указанные в алфавитах символы должны быть различимы с учётом регистра. Знак `$` зарезервирован за концом входа и в цепочке не вводится.

## Контрольные примеры

| Грамматика | Что посмотреть |
|---|---|
| `examples/lr2.cfg` | При k = 1 в I4 конфликт свёрток `A → c` и `B → c` на контексте `a`. При k = 2 ячейки для `aa` и `ab` различаются. Сравните шаги для `caa` и `cab`. |
| `examples/epsilon.cfg` | При k = 0 в I1 конфликт допуска и сдвига. При k = 1 допуск на `$` и сдвиг на `a` разделяются. Сравните разборы `ε` и `aaa`. |
| `examples/lr0.cfg` | Простая бесконфликтная грамматика LR(0). Разберите `ab`, затем `ba`. |
| `examples/ambiguous.cfg` | Для `S → S+S \| a` при k = 1 возникает конфликт сдвига и свёртки. |

Файлы `.cfg` этой версии хранят грамматику и выбранное k в JSON формата версии 1. Доступны текстовый протокол проверки и разбора, а также экспорт графа в DOT для Graphviz. Для больших автоматов на экране показывается окрестность выбранного состояния, а в DOT сохраняется полный граф.

## Соглашения и ограничения

- Для k > 0 берутся до k ближайших непрочитанных терминалов. Если терминалов осталось меньше k, в конец контекста добавляется один маркер `$`. Маркер представляет конец входа.
- При k = 0 сдвиг, свёртка и допуск сравниваются при пустом контексте `ε`. При выполнении сдвига считанный терминал определяет переход. Допуск выполняется после исчерпания входа.
- Ситуация `[A → α·β, u]` показывает позицию в правой части правила. Её контекст `u` относится к продолжению после всего правила. Контекст в таблице ACTION соответствует непрочитанному входу в текущем состоянии.
- При достижении предела ресурсов приложение сообщает, что вычисление не завершено. Результат в таком случае не позволяет классифицировать грамматику. Пошаговый разбор ограничен 2 000 шагами.
- Обозначения грамматики, правый вывод и термин «магазин» согласованы с формулировками предоставленных лекций 1, 2 и 5. Соглашение о конце входа и строгое сравнение действий для k = 0 взяты из описания курсовой.

## Сборка из исходников

Требуется .NET SDK 8. Для запуска WinForms нужен Windows. Из папки `source`:

```powershell
dotnet build LrkChecker.sln -c Release
dotnet run --project Lrk.WinForms
dotnet run --project Lrk.Cli -- check ../examples/lr2.cfg 1
dotnet run --project Lrk.Cli -- trace ../examples/lr2.cfg caa 2
```

`Lrk.Core` строит канонические ситуации и таблицу, ведёт трассу разбора и формирует объяснения. `Lrk.WinForms` содержит интерфейс, `Lrk.Cli` использует то же ядро для проверки и вывода протокола в терминал. В папке `verification` сохранены результаты запуска CLI.
